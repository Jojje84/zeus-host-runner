# Zeus v3.1 bounded host adapter

This directory is a deployment/control-plane artifact. It is **not** part of the locked Host Runner image build context.

Purpose:

- keep Docker/host authority outside Zeus Production and outside the Host Runner container;
- expose only the existing 9-field typed protocol over a private Unix socket;
- authenticate the Host Runner process with Linux `SO_PEERCRED` and the exact allocated Runner UID;
- map only the five allowlisted operations (`candidate_preflight`, `build_rescue`, `inspect_image`, `run_rescue_test`, `cleanup_own_temp`) to fixed host actions;
- never evaluate shell text, accept arbitrary argv, forward the Docker socket, or handle credentials;
- preserve root-owned state/audit and fail closed on stale active work.

`zeus_host_adapter.py` is intended to run as a root-owned, systemd-socket-activated broker. The socket unit creates `/run/zeus-host-adapter/adapter.sock` as `root:zeus-host-runner` mode `0660`. The service reads a non-secret `/etc/zeus-host-adapter.env` containing the exact verified `ZEUS_RUNNER_UID` generated by the bounded bootstrap.

Committing these files does **not** install or enable the service. Live owner/mode/mount checks, exact UID/GID, Docker CLI/socket access, peer denial, audit, recovery and rollback remain `UNVERIFIED_UNTIL_HOST_EXECUTION`.

Important: the currently published Host Runner runtime still calls `executeMock()` from `daemon.js`. Therefore the Runner image must not be considered functionally ready merely because this host adapter exists. A single bounded Runner re-lock is still required to connect the daemon to this private host-adapter socket while preserving typed validation, idempotency/lease/recovery and fail-closed semantics.
